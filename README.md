# 사내 전자결재 앱 구축·운영

휴가·일반 기안을 올리면 결재자에게 Teams 승인 카드가 순서대로 가고, 결과가 앱 목록에 바로 반영되는 사내 전자결재 앱을 혼자 만들고 운영한 작업이다.

> 회사 업무로 만든 앱이라 수식·흐름 정의·화면 구성·데이터는 올리지 않고, **어떤 일을 했고 무엇을 판단했는지만** 적었다.

## 요구 분석과 공수 산정

- 화면설계서를 받아 요구 14개를 구현 가능·조건부 가능으로 나눠 사전 검증했다(첨부 방식, 기안번호 중복 방지, 조직 정보 조회 등).
- 처음 산정은 팀 개발 기준이라 90일이 넘었다. 1인 개발, 이미 써 본 플랫폼, 반복되는 화면 패턴을 반영해 다시 산정했다. 그래도 넘치는 기능(위임·대결, 병렬 결재, PDF 양식 등)은 빼지 않고 **2차 범위로 명시**했다.

## 설계

- **저장소 변경**: 화면설계서는 SharePoint 목록 안이었다. 결재자를 사용자 테이블과 연결해 부서·매니저까지 쓰고, 사내 자산관리 앱과 같은 환경에서 바로 연동하기 위해 Dataverse로 바꾸자고 제안하고 반영했다.
- **결재 상태 계산 위치**: 처음에는 흐름이 기안 행의 상태를 고쳤는데, 그 수정이 같은 흐름을 다시 실행시켜 무한 반복이 생겼다. 상태는 결재선 행들을 세어 앱에서 계산하고, 흐름은 결재선만 고치도록 역할을 나눠 반복을 없앴다.
- **역할 분담**: 입력·검증·임시저장·상신은 앱, 결재자별 승인 카드·응답 기록·결과 통보는 흐름, 결재기한 하루 전 알림은 예약 흐름이 맡게 했다.
- 사내에 이미 있던 것(공용 헤더, 승인 흐름의 기본 골격, 처음 이식한 결재선 팝업 샘플)과 직접 만든 것을 구분해 기록했다.

## 구현한 기능

- 기안 목록: 기간·상태·제목 검색, 열 정렬
- 휴가·일반 기안 작성, 임시저장, 상신을 한 화면에서 처리
- 결재선 지정 팝업(나중에 직접 새로 만들어 교체), 1번 결재자 기본값 = 매니저
- 잔여연차 자동 계산과 초과 신청 차단(연차휴가만 차감, 평일만 계산)
- 결재자 순서대로 Teams 승인 카드, 결과 메일, 결재기한 하루 전 리마인드
- 기안번호 `날짜-순번` 형식 발번
- 폰 화면 대응

## 운영 중 해결한 문제

- **바로 상신하면 결재선이 안 생김**: 자동 번호가 저장 직후에는 아직 없어 빈 키로 결재선을 만들다 조용히 실패하고 있었다. 실제 데이터로 확인한 뒤 저장 후 다시 읽어 번호를 얻게 했다.
- **임시저장 건을 다시 저장하면 행이 중복 생성**: 저장 방식을 바꿔 기존 행을 고치도록 했다.
- **승인 카드가 2~3장 나감**: 승인 기록의 소유 계정을 비교해, 내 계정에서는 보이지 않던 **다른 계정이 만든 테스트 흐름**이 같이 실행되고 있음을 찾아 조건을 막았다.
- **카드의 휴가 날짜가 하루 앞당겨짐**: 처음 고친 식이 오류를 내자 같은 날 되돌렸다. 이후 열별 시간대 설정을 확인해 원인을 확정하고 필요한 곳만 고쳤다.
- **카드 링크를 눌러도 목록만 보임**: 앱 시작 화면 설정을 바꿔 링크로 들어오면 해당 기안 상세가 바로 열리게 했다.
- **고객명이 카드·메일에서 빈칸**: 연결 열은 흐름에서 키 이름이 다르다는 것을 찾아 고쳤다.
- **폰(390px) 대응**: 고정 폭 화면을 데스크톱은 그대로 두고 폰에서만 줄어들게 했다. 폰 전용 결재선 줄과 버튼 줄 수 계산도 넣었다.

## 일하는 방식

- 원인은 데이터와 실행 기록으로 먼저 확인하고 고쳤다.
- 고친 뒤에는 게시본 소스를 내려받아 바뀐 곳이 의도한 곳뿐인지 비교했다.
- 9월 변경 사항은 게시본으로 목록부터 상신·결재·리마인드까지 통합 테스트했고, 거기서 찾은 4건을 고쳤다.
- 다른 앱과 공유하는 원본 흐름은 건드리지 않고, 앱 전용 흐름을 따로 두어 운영했다.

## 남은 과제
